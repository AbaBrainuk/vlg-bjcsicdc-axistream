This repository contains the files for the competition problem I reconstructed from memory after the contest.

Here is what happened: I spent a long time preparing for the 2026 Beijing College Students IC Design Competition, only to see everything fall apart because of severe sleep deprivation. I managed just three and a half hours of sleep the night before the competition. As the event wore on, my brain was completely overloaded — I could recognize every word in a piece of code, but had no idea what the lines meant when put together, and I completely lost the ability to reason about signal timing. Even though I had essentially finished coding all the modules and had a clear architectural plan, I had no mental energy left to debug or refine anything. My mindset collapsed. In the end, I scribbled a report and submitted it. At one point, I was genuinely ready to hand in a blank paper. Obviously, all my effort for this competition amounted to nothing on that day.

After the competition, once I had fully recovered, I decided to try solving the problem again — this time without AI tools or search engines, relying entirely on my own understanding. A few hours later, I had reconstructed the solution from memory. That is what you see in the files above.

A rough summary of the problem:
Design a computation module that performs multiplication and addition on an incoming 4×4 matrix. The multiplication is the Hadamard product, and the addition is the sum of all elements within the matrix. To accomplish this, three modules must be designed: a decoder, a product module, and a summation module. The port definitions of these modules were fixed and could not be changed; only necessary additional signals could be introduced. All communication between modules had to use streaming transmission. Refer to the module definitions in the code for the specific requirements (comments are written in Chinese). The input signals use a simplified AXI-Stream protocol.

This, however, is my own condensed version of the problem. The actual competition description was long-winded and contained many redundant, contradictory, and unclear parts. For example, in practice, the multiplication module does not need to store everything before computing — that would be inefficient — yet the original problem description insisted on receiving everything first before performing the operation. These kinds of ambiguities only made my already overloaded brain even more confused at the time... On a side note, I genuinely want to grumble: if only the top-level interface was required to use streaming, and the internal modules were free, the whole thing could have been done quickly and easily with a pipeline — and it would even be more efficient. But the competition rules forced every module to use streaming transmission, which was painful.

I am not a communications major, nor do I study related courses. Learning Verilog HDL, FPGA, and all this stuff is purely a personal hobby. So even in a sober post-competition state, there may still be all sorts of mistakes in the code.

In any case, I hope these files can serve as a reference for anyone who wants to take part in this competition or a similar one in the future. And please, please get enough rest before the contest. Don't repeat my regret
